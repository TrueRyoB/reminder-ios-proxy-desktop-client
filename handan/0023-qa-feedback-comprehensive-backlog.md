# 0023: 実機QAでのユーザーフィードバックを受け、包括的なQAバックログを作成

**日時**: 2026-07-26

## 経緯
GUI-1〜GUI-11の実装完了後、ユーザー立ち会いの下で初めての実機起動確認を実施。
その過程で「ウィンドウが非表示のまま起動する」バグを発見・修正(handan本文参照)。
その後ユーザーから3点の具体的な指摘を受けた:
1. 読み込みが遅い(0.1秒帯を要求)
2. ダッシュボードの目的が違う(件数表示ではなく、上から順にこなせば良い
   優先度付きタスクキューであるべき)
3. 新規タスク追加ボタンが機能しない

ユーザーは明示的に「これに閉じていないことを了承してください」と述べ、
この3点に限定せず、アプリ全体のQA観点を包括的に洗い出すことを求めた。

## 発見した実バグ: ウィンドウ非表示起動
`lib.rs`の`setup()`フックでトレイアイコンを構築した後、メインウィンドウを
明示的に`show()`していなかったため、トレイアイコン機能追加(GUI-8)以降、
Windows上でメインウィンドウが非表示のまま起動するようになっていたと判明。
`Get-Process`の`MainWindowHandle`は代わりに内部の`Tao Thread Event Target`
(14x14の非表示ヘルパーウィンドウ)を指しており、実際の`Tauri Window`
(正しいサイズ、しかし`IsWindowVisible=False`)を見逃していた。
`EnumWindows`で全ウィンドウを列挙し原因を特定、`setup()`内で
`window.show()?; window.set_focus()?;`を追加して修正。

## 発見した実バグ: 「＋」ボタンの無反応
`bindCreateSheet`のクリックハンドラが`currentView.kind !== "list"`のとき
無言でreturnする設計。GUI-11でダッシュボードをデフォルト画面にした結果、
起動直後は常にこの条件に該当し、ボタンが無反応になっていた。
