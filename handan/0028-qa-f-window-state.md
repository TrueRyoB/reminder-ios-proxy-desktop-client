# 0028: QA-F(ウィンドウ状態の永続化)実装・実地検証完了

**日時**: 2026-07-26

## 実装内容
公式`tauri-plugin-window-state`(v2.4.1)を導入。ウィンドウの位置・
サイズ・最大化状態を再起動を跨いで保持する。

- `gui/src-tauri/Cargo.toml`: `tauri-plugin-window-state = "2"`を追加。
- `lib.rs`: `.plugin(tauri_plugin_window_state::Builder::default().build())`
  を登録。
- トレイの「終了」メニューハンドラに`app.save_window_state(StateFlags::all())`
  を明示的に追加してから`app.exit(0)`するよう変更。

## 調査で判明した重要な事実
このプラグインは**アプリ終了時にのみ**状態を保存する設計であり、
リサイズ/移動のたびに自動保存する訳ではない(WebSearchで公式ドキュメント/
ソースを確認)。このアプリはCloseRequestedをフックしてウィンドウを
「閉じる」のではなく「隠す」設計(トレイ常駐、GUI-8参照)のため、
**通常のウィンドウクローズでは終了イベントが発火せず、保存されない**。
このため、トレイの「終了」メニューハンドラで明示的に保存を呼ぶ実装が
必須と判断した。

## 検証内容(実地検証)
1. 一時的にCloseRequestedフックを無効化(ウィンドウが実際に閉じる状態に戻す)
   → `cargo tauri dev`で起動→ウィンドウを(300,250)・900x700にリサイズ/移動
   → `WM_CLOSE`を送信して実際にプロセスを終了させる
   → `%APPDATA%\com.trueryob.reminderproxyclient\.window-state.json`が
   生成され、リサイズ後の値(DPIスケール後: width=1107, height=828,
   x=375, y=313)が保存されていることを確認。
2. 再度`cargo tauri dev`で起動 → ウィンドウが実際に(300,250)・900x700
   (設定した値と一致)で復元されることを確認(tauri.conf.jsonのデフォルト
   800x600ではない)。
3. 検証後、一時的な変更を元に戻し(`prevent_close()` + `hide()`の
   hide-to-tray動作を復元)、`cargo clippy`で警告なしを確認。
4. `WM_CLOSE`を送信してもプロセスが生存し続ける(hide-to-tray動作が
   正しく復元されている)ことを再確認。
