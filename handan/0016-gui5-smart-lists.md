# 0016: GUI-5(スマートリスト)完了・検証済み

**日時**: 2026-07-26

## 実装内容
純粋にフロントエンド側の集計ロジックのみ(新規Rustコード・新規Tauriコマンドなし。
既存の`list_lists`/`list_reminders`を全リストに対して呼び、クライアント側で
フィルタ・ソートする)。

- サイドバーPanelに「スマートリスト」セクション(今日/予定/フラグ付き/すべて)
  を「マイリスト」セクションの上に追加。
- `fetchAllReminders()`: キャッシュ済み`cachedLists`(直近の`list_lists`結果)
  の全リストに対し`list_reminders`を並行取得(`Promise.all`)し、
  `listTitle`を付与して集約。
- `selectSmartList(kind, title)`:
  - **今日**: `dueDate <= 本日23:59:59.999`(期限切れも含む、ネイティブアプリの
    Todayビューと同じ挙動)。**降順**(直近の期限が先頭)でソート
    — 計画書に記載の意図的な改善点(ネイティブアプリのTodayは昇順で
    古い期限切れ項目を先にスクロールしないと見えないという批評記事の指摘を
    踏まえた設計)。
  - **予定**: `dueDate`が存在するもの全て、昇順ソート。
  - **フラグ付き**: `flagged === true`のもの。
  - **すべて**: フィルタなし。
  - 集約ビューでは各行に`listTitle`をフッターとして表示し、どのリスト由来か
    分かるようにした(単一リスト表示とは`renderReminders`の`showListTitle`
    引数で区別)。

## 検証内容
1. `npx tsc --noEmit`(gui/) — 型チェック通過。
2. `cargo tauri dev`を実行し、`Get-Process -Name gui`で`MainWindowHandle`が
   有効かつ`Responding: True`であることを確認(実データでの`list_lists`/
   `list_reminders`自動実行を含む起動シーケンスがクラッシュしないことを確認)。

## 意図的に省略した検証(スコープの明示)
今回は**実データの画面キャプチャによる内容確認を意図的に行わなかった**。
理由: handan/0014で発生した「実データのパスワードがスクリーンショットに
写り込む事故」の直後であり、スマートリスト(特に「すべて」「今日」)は
定義上すべてのリストの実データを横断集約するため、画面キャプチャによる
検証は同種の情報露出リスクを再度生むことになる。フィルタ・ソートロジック
自体は型チェック済みかつ単純(filter/sort相当)であり、既にGUI-4で実証済みの
`list_reminders`呼び出しパターンをそのまま複数リストに適用しているだけ
なので、コードレビュー + 型チェック + クラッシュしないことの確認を
もってこのマイルストーンの検証として十分と判断した。
