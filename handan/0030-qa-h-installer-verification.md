# 0030: QA-H(MSI/NSISインストーラの実インストール動作検証)完了

**日時**: 2026-07-26

## 実施方針(判断根拠)
インストーラの実行はシステム状態を変更する操作(レジストリ・ファイル
システムへの書き込み)であり、これまでの検証(ephemeralな`cargo tauri dev`
プロセス実行)より一段階リスクが高い。ただし、以前のMSVC Build
Toolsインストール(数GB・共有ツールチェーンへの影響)とは性質が異なり、
今回は**自分自身がビルドした自己完結型アプリの、ユーザー単位(per-user)
インストール**であり、影響範囲は`%LOCALAPPDATA%\gui`とレジストリの
アンインストールエントリのみ、かつ標準のアンインストーラで完全に
元に戻せる。この判断に基づき、サイレントインストール→動作確認→
サイレントアンインストール→クリーンアップ確認、という手順で
自律的に実施した。

## 前提: リリースビルド成果物の再生成
handan/0025のビルドキャッシュ破損対応(`cargo clean`)により、GUI-10で
生成したMSI/NSIS成果物も削除されていたため、`cargo tauri build`で
再生成した(3分弱で完了、問題なし)。

## 実施内容と結果
1. `gui_0.1.0_x64-setup.exe /S`(NSIS標準のサイレントインストールフラグ)
   でインストール → exit code 0。
2. レジストリ(`HKCU:\...\Uninstall\gui`)を確認し、実際に
   `%LOCALAPPDATA%\gui`にインストールされたことを確認。
   `gui.exe`/`uninstall.exe`の存在を確認。
3. インストール済みの`gui.exe`を直接起動 → `Get-Process`で有効な
   `MainWindowHandle`/`MainWindowTitle='gui'`/`Responding: True`を確認
   (QA-Gで修正したウィンドウ復元も含め、リリースビルドで問題なく動作)。
   同時に、以前から判明していたセッション期限切れ(421エラー)による
   ログイン画面遷移も一貫して発生し、異常な追加の不具合は見られなかった。
4. プロセス終了後、`uninstall.exe /S`でサイレントアンインストール →
   exit code 0。
5. `%LOCALAPPDATA%\gui`ディレクトリの削除、レジストリの
   アンインストールエントリの削除を確認。システムを検証前の状態に
   完全に復元した。

## 見送った項目
- MSI(`.msi`)側の同様のインストール検証は行わなかった(NSISと同じ
  `cargo tauri build`パイプラインの成果物であり、リスク/工数対効果を
  考慮してNSIS側の検証で代表させた)。
- 自動アップデート機構は現時点でスコープ外(ユーザー確認が必要な
  設計判断のため、実装せずバックログにも起票していない。必要であれば
  今後ユーザーに確認する)。
