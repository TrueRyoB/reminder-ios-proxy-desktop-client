# 0035: U1〜U4 を upcoming コレクション+メタタグで解決・実装

**日時**: 2026-08-01

## 著者の方針(逐語要旨)
- U1/U2: 「カスタムコレクション "upcoming" を作成して、これの期限が到来した
  タイミングで、新しく決めていたタスクカードを任意のコレクションに追加する。
  基本的に習慣系と紐づいている」
- U3/U4: 「keyの登録・keyに基づくタスク抽出などのロジックはローカルストアで
  完結させる。各タスクが何の属性に紐づいているかはメタタグを記す([]で囲むなど)」

## 設計上の意味
- 開始可能時間(defer)を新フィールドでなく**コレクション所属**で表現する。
  参照面の資格規則が「課題あり ∧ upcoming にいない」に拡張され、U1 が
  述語1つで解ける。
- 習慣 = upcoming カードの発火→産み込み→再装填ループ。開始(発火日)と
  終了(産むカードの締切 = 発火日+Nオフセット)が独立(U2)。
- 属性タグの担体を**タイトル内 `[キー]`**にしたことで、iOS 可視・複数付与・
  ローカルストア消失耐性を同時に獲得(U3)。README コア価値3の「メタタグを
  駆使して分類粒度を増やす」構想の回収。語彙(キー一覧)のみローカル(U4)。

## 実装
- Rust: `ProxyMeta` に targetList / repeatDays / dueOffsetDays を追加。
  `ProxyStore.env_keys`(登録キー語彙)+ `set_env_keys` コマンド。
  `watch.rs::process_upcoming`: upcoming リスト(タイトル一致・大文字小文字
  無視)の期日到来カードから行き先へ `create`(締切は終日担体)、繰り返しは
  取り逃しを now を跨ぐまで進めて再装填、一回きりは完了で消化。upcoming は
  通知ループから除外(待機庫は鳴らない)。
- Front: 投函4入口目「＋あとで」(upcoming が存在するときだけ表示。タイトル・
  サイズ・開始日・行き先・繰り返し・締切+N日)。編集シート: 環境 select を
  廃止し**タグチップ**(登録キーのトグル=タイトルの [キー] を書き換え)+
  「＋キー」登録。upcoming のカードには行き先/繰り返し/締切+N日の行を表示。
  参照面・検索・残高・編成候補から upcoming を除外。全表示箇所でタグを
  剥がしてバッジ化。編成スコアの環境一致はタグ集合で判定。

## 検証
`npx tsc --noEmit` / `vite build` / `cargo clippy -D warnings` /
`cargo test --workspace --exclude gui`(5件) — 全通過。バックエンド再ビルド後、
起動・応答確認済み。

## 運用前提・既知の限界
- **upcoming リストは iOS 側で一度作る**(リスト CRUD 未実装のため。
  handan/0031 の見送りを維持)。無ければ機能は静かに眠る。
- 発火はポーラー周期(5分)粒度。日付単位の運用では十分。
- 産み込みと再装填の間でプロセスが落ちると重複産みの可能性(次回ポーリングで
  は再装填済みのため増殖はしない)。v1 では受容。
- ProxyMeta.env は廃止(後方互換のため残置)。
